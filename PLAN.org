#+title: Songs planning ledger
#+filetags: :planning:
#+TODO: TODO DOING | DONE CANCELLED

Every change to this repository is written down here as a goal before
it is made, and linked to its commit and its resolving location after
it lands. The file is plain Org text: GitHub renders it, and any
editor can maintain it.

* Conventions
** The rule
1. *Before* writing, adding or changing any file, add a =TODO= entry at
   the top of [[#tasks][Tasks]] stating the goal.
2. Do the work. Then mark the entry =DONE=, add a =CLOSED= timestamp,
   and tag it =pending_commit=. Point each =Resolved in= line at the
   file, section or function that resolves the goal, using the
   provisional link form (=main= in place of a SHA), and leave
   =Commit :: pending=.
3. Commit. Immediately afterwards run ~git log -1 --format='%H %s'~,
   replace =pending= with a link to that commit, replace =main= in each
   =Resolved in= link with that SHA, and remove the =pending_commit=
   tag. This bookkeeping edit rides in the next commit, whatever that
   commit is for. It never gets an entry of its own, and it is never
   done with ~git commit --amend~, which would change the SHA just
   recorded.

The tag marks the waiting state because it sits on the headline where
it cannot be missed, and ~grep -n pending_commit PLAN.org~ lists
everything still waiting on git. The =DONE= state stays truthful (the
work is done); the tag records only that the ledger is waiting.

** Entry template
Written when the goal is set:
#+begin_example
  ** TODO <Goal, as one imperative sentence>
  :PROPERTIES:
  :CUSTOM_ID: <short-kebab-slug>
  :END:
  <One or two lines on what and why.>
  - Commit :: pending
  - Resolved in :: [[https://github.com/Conaws/songs/blob/main/<path>][<path>]] (whole file)
#+end_example

Done, waiting for the commit (the CLOSED timestamp is written by hand):
#+begin_example
  ** DONE <Goal>                                            :pending_commit:
  CLOSED: [2026-11-27 Fri 00:12]
  :PROPERTIES:
  :CUSTOM_ID: <short-kebab-slug>
  :END:
  <What and why.>
  - Commit :: pending
  - Resolved in :: [[https://github.com/Conaws/songs/blob/main/Milton/foo.md#some-section][Milton/foo.md, section "Some Section"]]
#+end_example

After the commit lands:
#+begin_example
  ** DONE <Goal>
  CLOSED: [2026-11-27 Fri 00:12]
  :PROPERTIES:
  :CUSTOM_ID: <short-kebab-slug>
  :END:
  <What and why.>
  - Commit :: [[https://github.com/Conaws/songs/commit/<sha>][<sha7> <subject>]]
  - Resolved in :: [[https://github.com/Conaws/songs/blob/<sha>/Milton/foo.md#some-section][Milton/foo.md, section "Some Section"]]
#+end_example

** Link forms
Permalinks use the full 40-character SHA, so they never move. Before
the commit exists, write the same link with ~main~ in place of the SHA;
it resolves as soon as the push lands and is swapped for the pinned
form in step 3.

| What the entry resolves            | Permalink                                                               |
|------------------------------------+-------------------------------------------------------------------------|
| The commit                         | ~https://github.com/Conaws/songs/commit/<sha>~                           |
| A whole file (new or rewritten)    | ~https://github.com/Conaws/songs/blob/<sha>/<path>~                      |
| A function or block in a code file | ~https://github.com/Conaws/songs/blob/<sha>/<path>#L<from>-L<to>~        |
| A section of a Markdown file       | ~https://github.com/Conaws/songs/blob/<sha>/<path>#<heading-slug>~       |
| Exact lines of a Markdown/Org file | ~https://github.com/Conaws/songs/blob/<sha>/<path>?plain=1#L<from>-L<to>~ |

- GitHub has no anchor for a function by name. A line range at a fixed
  SHA is permanent, so link the full span of the definition.
- Heading slugs follow GitHub: lower-case, spaces become hyphens,
  other punctuation is dropped. ~# Better to Reign in Hell (Book 1, lines 242-270)~
  becomes ~#better-to-reign-in-hell-book-1-lines-242-270~.
- On any GitHub file page, pressing =y= rewrites the URL into a
  SHA-pinned permalink; select lines first to get the ~#L~ range.

** Rules
- One entry per goal. Several goals landing in one commit each get
  their own entry, all pointing at the same commit.
- A goal that lands over several commits gets one =Commit= line per
  commit and keeps the tag until the last one is recorded.
- Abandoned goals become =CANCELLED= with a one-line reason and no
  links.
- Commit messages name the entries they complete, one
  ~Plan: <slug>~ line each in the body, so a commit leads back to its
  goal.
- Never rewrite history the ledger points at. If it happens anyway
  (rebase, squash), update every SHA that changed.
- New entries go at the top of Tasks, so open work is seen first.
- Only this file's own bookkeeping (filling in SHAs, removing the tag)
  is exempt from needing an entry. Everything else needs one,
  including edits to CLAUDE.md, AGENTS.md and this Conventions
  section.
